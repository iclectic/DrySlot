# Prioritised implementation backlog

Created 29 October 2026 from Phase 0 audit at `3baf32c`. **Every task below is proposed and not started.** Phase 1 requires owner review of the Phase 0 pack first. IDs are stable; listed order prioritises prerequisites and unsafe current behavior. Future packages should have their own branches (for example `fix/DS-003-weather-unavailable`) and meet the eight-part work-package report in `docs/ENGINEERING_RECORD.md`.

Test paths below are proposed new tests unless explicitly identified as existing. Keep unit/contract/widget tests alongside each change; Phase 9 expands verification rather than postponing it. Minimum CI is brought forward because safe Phase 1 changes need enforcement. Later phases do not have permission to upload or publish.

## Decisions required before dependent work

Phase 0 review is the immediate gate. Subsequent owner decisions are commercial provider rights/budget and mobile credential constraints; supported OS/device scope; whether existing store IDs/listings must be preserved; which stranded features to reconnect; and permitted telemetry/feedback handling. Work on independent, authorised packages can proceed after Phase 0 review while unresolved dependent gates remain explicit. No delivery dates, costs, user demand or account capabilities are assumed.
