## Release disposition and residual risk

P0 risks are gates, not promises that Phase 1 alone will implement every later-phase feature. Phase 1 should remove unsafe current behavior and establish a buildable baseline; duration-aware activity recommendations and provider contracts remain subsequent P0 work. Deferred P2 features must not be advertised as shipped. All closures need a linked change plus executed verification. No risk is closed by this documentation package.
